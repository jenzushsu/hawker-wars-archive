The offline engine initializes the frozen opening ledger and implements all five actions, eight tick stages, capacity reservations, expiry, FIFO service/admission, abandonment, supplier effects and closing settlement. ## Verification

Commands: `pnpm install --frozen-lockfile`, `pnpm check`, `pnpm demo:rules 0 clean` and the four-scenario development reference check. `pnpm check` includes:

- Strict TypeScript checking and the original P0 contract/drift checks.
- **188 passing tests** across eight test files, including independent demand/hash golden vectors, lifecycle/FIFO/economy boundaries, actual observation construction, mock/fallback attribution, diagnostic integrity and deterministic execution with different operational metadata.
- All **30 frozen numerical fixture cases and 88 expectations** executed against real functions; expected fixture data remains unchanged.
- Rules development seeds **0–99 × four scenarios × two passes = 800 completed episode executions**, comparing actions, prepared/committed hashes, terminal hashes, scores and metrics.
- **40 mixed legal-action cases × two passes = 80 additional episode executions**, covering all five actions with explicit offline mock provenance.
- Four development reference cases checked against actions, per-boundary hashes, scores, metrics, configuration identity and source/toolchain/input identity.

The standalone validation replaces global fetch with a throwing guard. Implementation imports contain no provider SDK, HTTP or account clients. All executions are offline; no provider trial quota or approved Zoom budget is consumed. Development seed validation explicitly excludes held-out seeds.

Independent review found and corrected acceptance of illegal probability-action entries and invalid individual wait values that could corrupt secondary metrics. Separate regressions cover both. Input frames remain immutable, and the test harness uses explicit opening ledgers for synthetic local fixtures without relaxing ordinary episode accounting.
